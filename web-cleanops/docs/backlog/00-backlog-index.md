# Backlog Documentation Index

## Purpose

This folder contains CleanOps backlog and development priority documentation.

The backlog defines what should be built, stabilized, validated, postponed or explicitly deferred.

Use this folder before implementation starts, especially when a feature affects architecture, operational workflows, Supabase-backed data, permissions, automation, scheduling, requests, keys or Development Center tracking.

---

## Documents

### 20-build-backlog.md

Defines the current development backlog and implementation priorities.

This document should be used to track planned work, active work, deferred work and major follow-up items.

All implementation work should be checked against this document before coding begins.

If a new feature, module or architectural change is not represented in the backlog, the backlog should be updated before implementation starts.

---

## Backlog Responsibilities

The backlog should help answer:

1. What should be built next?
2. What is already planned?
3. What is blocked?
4. What is deferred?
5. What depends on another module?
6. What must be validated before release?
7. What should not be implemented yet?
8. What has been intentionally paused?

---

## Recommended Backlog Categories

Backlog items should be grouped by module or workstream when possible.

Recommended categories:

- Core Operations
- Schedule
- Requests
- Keys / Access Management
- Customers
- Employees
- Agreements
- Time Reporting
- Payroll Basis
- Invoice Basis
- Operations Center
- Automation
- AI-assisted workflows
- Development Center
- Supabase migration
- Data cleanup / test data
- Technical debt
- Release readiness
