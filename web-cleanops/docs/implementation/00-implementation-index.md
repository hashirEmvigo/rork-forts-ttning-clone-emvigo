# Implementation Documentation Index

## Purpose

This folder contains implementation plans for CleanOps modules.

Implementation documents translate approved architecture into phased build plans, technical tasks, validation steps and rollout sequencing.

Architecture defines what the system must be.

Implementation defines how the system should be built.

---

## Module Folders

### requests/

Implementation documentation for Request Management.

### keys/

Reserved for KEYS implementation documentation.

This folder should contain phased implementation plans for key/access management, schedule access analysis, automation, admin dashboarding, employee app behavior and Development Center validation.

---

## Rules

Before implementation starts:

1. Read `/docs/00-master-index.md`.
2. Read the relevant architecture document.
3. Read the relevant backlog item.
4. Create or update the implementation plan.
5. Define controlled phases.
6. Define validation requirements.
7. Define manual test scenarios if the feature is operationally sensitive.
8. Update Dev Center tracking when implementation begins or changes.
